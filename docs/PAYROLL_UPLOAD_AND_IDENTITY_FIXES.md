# 资料采集、大文件上传与重复工资条修复

适用版本：2026-11-02，本地薪酬核算中心。

## 1. 自动采集结果不再笼统显示“明确未提供”

原逻辑把支付绑定、违规扣款、骑手账单、欺诈单、问题单、价格档案放入同一个可选资料执行器。一项需要登录或人工验证时，会取消这一整组；合并层随后把各类错误覆盖为“本次资料未提供”。

修改后仍只有一个公开任务、每种资料一份结果，内部逐项执行。某项需要认证、下载失败或文件不可读，只影响这一项，其他资料继续。用户主动中断则停止整个任务。

错误经过脱敏后写入执行日志，并通过批次资料状态传递到结果工作簿“核算资料说明”。说明区明确区分“已提供”和“未参与核算”，后者附具体原因。没有恢复失败项清单、重试按钮、人工扣款确认或额外操作步骤。

继续沿用现有业务策略：模板和配送费可读取才执行；其他资料缺失可继续，支付绑定标记未校验、价格缺失标记无单价。旧批次已经丢失的具体错误无法事后还原，不能把旧批缺项宣称为已恢复。

## 2. 保留上传操作，支持1–2GB资料

用户仍选择文件、文件夹或拖放。没有新增分块上传/断点续传步骤。

浏览器用原File对象组装STORE ZIP，按1MiB读取计算CRC，避免把全部文件转换成完整内存字节数组；展示整理与传输进度，并支持ZIP64大小和偏移。

服务器接收文件使用唯一名称，避免同时上传覆盖source.zip。解压交给Python标准ZIP读取器，按1MiB读写到磁盘，解压前检查目录、声明大小与磁盘空间，解压过程中核对实际字节数和CRC。手动资料校验及日账单内部解压的旧大小门槛一并调整。

| 限额 | 当前值 |
| --- | --- |
| 单文件解压后大小 | 4GiB |
| 单批解压后总量 | 10GiB |
| 文件条目数量 | 2000 |
| 外层上传包传输大小 | 11GiB |
| 接收请求超时 | 1小时 |
| 解压子进程超时 | 30分钟 |

文件大小超限、总量超限、重复路径、路径越界、加密/损坏ZIP、磁盘不足分别提示，不再合并成“越界/重复路径或过大文件”。保留既有路径边界保护；上传失败不覆盖旧批资料或工资结果。

## 3. 同站同骑手不同姓名只生成一条工资

原工资名册按站点、骑手ID、姓名去重。同一骑手ID在来源资料中出现不同姓名写法时，会产生两行工资和扣款。

修复后工资、扣款名册按站点与骑手ID唯一生成，姓名不参与身份去重。显示姓名优先同站申请名单，其次该骑手唯一申请姓名，否则选择最新日期的非空来源姓名。提前保存申请名单身份列，避免价格解析复用列索引后错读姓名。

原始订单和日单量来源分组保持原样，原计薪公式、价格匹配、扣款金额规则均不更换。合法跨站记录保留各自工资条。

## 验证与已有结果

联合回归286项后台、163项前端通过，包含异名去重、跨站保留、订单/天数/扣款不扩大、认证隔离、错误脱敏和ZIP安全检查。生产构建通过。

原505MB资料、2,148,200,042字节合成资料和4GiB单文件ZIP64边界均已在隔离HTTP接收端完成真实Edge浏览器组包、multipart传输和解压，按原字节恢复。耗时分别为5.03秒、30.57秒、55.98秒，仅代表当前机器实测，不是通用性能承诺。另有超过2GiB资料通过手动资料头部预检；未将2GiB合成资料执行完整工资核算。详细实测证据位于本次本地验证目录。

历史批次只使用经SHA256核对的保留输入在独立目录生成复核版本，不补发平台导出、不覆盖原工作簿。该复核版本不能补齐原批次未取得的资料，需在Excel/WPS刷新公式后复核；离线生成及行数核对不等于财务发薪验收。

保留输入复核确认重复身份键已消除，同一站点、骑手ID只生成一条工资和扣款记录，日单量合计与配送记录数前后一致。原输入、原结果及配置文件摘要保持不变。公开源码说明不包含骑手姓名、编号、实际扣款金额或业务明细。

扩展运行历史company_merge测试时，两项旧断言失败；用旧名册算法对照亦复现。它们涉及空字段显示和小象调用计数，不属于本次三项修复，未借此更改既有业务逻辑。
