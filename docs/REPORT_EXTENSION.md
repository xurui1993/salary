# 专项报表扩展约定

## 页面与业务分工

`src/components/ReportBuilder.tsx` 只负责报表目录、城市/时间控件、范围摘要和提交动作；执行、认证、文件留存、恢复与任务记录沿用现有服务。

后端 `backend/task_catalog.py` 的 `REPORTS` 是页面使用的报表目录。`GENERATORS` 从目录派生，`/api/fengshen-downloads/options` 的 `generators` 返回可供页面展示的定义，前端不再逐张硬编码报表卡片。

## 增加一张报表

1. 在 `REPORTS` 注册唯一 `id`、`label`、`description`、`systems`、`scope` 和 `station_rule`，声明 `_source_labels` 或 `_source_group`。来源组引用生成器真实依赖，不能只写展示说明。
2. 在业务服务中注册对应数据集、来源依赖和实际生成处理器，保证产出与范围匹配。新增业务逻辑仍需要实现与验证，不能只添加目录后就认为可执行。
3. 为范围校验、缺项、恢复、产出文件和业务规则添加测试。使用现有任务请求编号、回执及完整性校验，不自行另建一套任务/下载机制。

已有范围控件：

| scope | 页面行为 |
| --- | --- |
| `city_month` | 多城市、开始/结束月份；按月份拆分。当前月请求不发送未来日期。 |
| `city_range` | 多城市、开始/结束日期。业务服务须实现实际区间语义与校验。 |
| `all` | 明确显示全部城市、当前全量；不提供不生效的城市或日期筛选。 |

`station_rule='separation'` 显示“排除取分离/仅取分离”；`none` 不发送此选项。

## 保持的行为

- 城市必须来自真实配置且可用，后端再次校验。
- 专项报表的城市、月份与其他数据采集模块分别记忆；跨模块明确带入的范围优先使用。
- 提交范围摘要在同一页面显示；新报表提交成功后进入任务记录。重复请求和结果不明确时沿用原请求编号与冻结参数。
- 所需资料默认折叠；不虚构数据齐套、平台认证或人工复核结果。
- 工资计算规则、原始文件和恢复回执不由页面组件修改。
