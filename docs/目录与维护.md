# 目录与维护

根目录只保留：启动系统.cmd、README.md、app、docs。

app/backend 是 Python 处理与认证逻辑，app/src 是前端，app/server 是服务层；app/public 与 app/system_templates 是静态资源和必需模板，app/tests 与 backend/tests 是维护测试。

首次启动自动生成 app/dist，由 app/dist/server.js 同时提供前端页面和 API 代理，不再拆分为多空间进程。

平台会话与业务数据在运行时生成，保存在 app/data、app/uploads、app/outputs、app/backend/.local_auth、app/backend/.local_downloads 和 app/runtime；源码发布必须排除这些目录、依赖、缓存及日志。

在 app 目录执行 npm ci、npm run lint、npm test、npm run build。npm run clean 仅清除构建产物。后端使用项目虚拟环境运行 backend/run_tests.py；独立测试需使用其隔离配置，不能引入真实业务资料。运行后端测试请设置 PYTHONIOENCODING=utf-8，否则用例中的中文与符号输出会触发 GBK 编码错误。

发布源码包在 app 目录执行 `python scripts/pack_home_package.py <输出zip路径>`，输出目录应在本项目之外。脚本只收录启动入口、README、docs 说明和 app 源码、测试与必需模板，排除依赖、构建产物、业务数据、平台会话、下载缓存、日志与任何 .local_auth/.local_downloads 备份，并逐文件校验 ZIP CRC 与 SHA-256，同时刷新 docs/SOURCE_MANIFEST.json 与 docs/SHA256.txt。

历史版本报告、维护证据、回退备份和浏览器级 QA 探针留在源码目录之外，不随本包重复交付。业务公式、模板和计算规则保持原有实现。
